# Эмулятор UNIX-подобной командной строки (Вариант №18)

Кроссплатформенный эмулятор командной строки на Python, имитирующий работу UNIX-подобной оболочки. Программа использует виртуальную файловую систему (VFS), которая загружается из CSV-файла в оперативную память. Все операции с файлами и каталогами выполняются внутри VFS и не изменяют реальные файлы на диске.

## Поддерживаемые команды

* `ls` — просмотр содержимого текущего или указанного каталога.
  * `-l` — подробный список с информацией о владельце и группе файлов.
* `cd` — переход в указанный каталог.
* `pwd` — вывод пути текущего каталога.
* `cat` — вывод содержимого текстового файла.
* `uniq` — фильтрация повторяющихся соседних строк файла.
  * `-c` — вывод количества повторений каждой строки.
  * `-d` — вывод только повторяющихся строк.
  * `-u` — вывод только уникальных строк.
* `du` — отображение размера файлов и каталогов.
  * `-a` — вывод размеров файлов и каталогов.
  * `-h` — отображение размеров в удобном для чтения формате.
  * `-s` — вывод только общего размера.
* `touch` — создание пустого файла в виртуальной файловой системе.
* `chown` — изменение владельца и группы файла или каталога.
  * `-R` — рекурсивное изменение владельца и группы для каталога и его содержимого.
* `exit` — завершение работы эмулятора.

## Запуск эмулятора

Для запуска программы перейдите в корневую директорию проекта и выполните команду:

```bash
python shell.py
```

Также поддерживается запуск с передачей параметров командной строки:

```bash
python shell.py --vfs vfs.csv --prompt "user@vfs:/$ " --startup-script examples/startup.sh
```

Параметры запуска:

* `--vfs` или `--vfs-path` — путь к CSV-файлу виртуальной файловой системы.
* `--prompt` — пользовательское приглашение командной строки.
* `--startup-script` или `--script` — путь к файлу со стартовыми командами, которые будут выполнены автоматически при запуске.

Если параметры не указаны, используются значения по умолчанию, заданные программой.

## Виртуальная файловая система

Виртуальная файловая система загружается из CSV-файла и полностью хранится в оперативной памяти.

* Поддерживается создание вложенных каталогов и файлов.
* Текстовые данные хранятся в обычном виде.
* Бинарные данные хранятся в формате Base64.
* Поддерживаются относительные и абсолютные пути.
* Изменения, выполненные командами `touch` и `chown`, действуют только во время работы программы и не изменяют исходный CSV-файл.

## Запуск автоматических тестов

Для проверки корректности работы эмулятора предусмотрены unit-тесты на базе стандартной библиотеки `unittest`.

Запуск тестов из корневой директории проекта:

```bash
python -m unittest discover -s tests -p "test_final.py" -v
```

Тесты проверяют работу парсера команд, виртуальной файловой системы, навигации по каталогам, чтения файлов, команд `uniq`, `du`, `touch`, `chown`, а также обработку ошибок, запуск стартовых скриптов и работу CLI.

## Примеры использования

Пример интерактивной сессии:

```text
user@hostname:/$ pwd
/

user@hostname:/$ ls
docs/  notes.txt  projects/

user@hostname:/$ cd docs

user@hostname:/docs$ ls
readme.txt  test.txt

user@hostname:/docs$ cat readme.txt
Hello, world!

user@hostname:/docs$ touch new.txt

user@hostname:/docs$ ls
readme.txt  test.txt  new.txt

user@hostname:/docs$ chown student:users new.txt

user@hostname:/docs$ ls -l
readme.txt  student:users
test.txt    student:users
new.txt     student:users

user@hostname:/docs$ cd ..

user@hostname:/$ du -sh
4.0K

user@hostname:/$ exit
```

## Стартовые скрипты

В проекте предусмотрены примеры стартовых скриптов для автоматической демонстрации работы команд.

Для запуска скрипта используйте параметр `--startup-script`:

```bash
python shell.py --vfs vfs.csv --startup-script examples/startup-stage5.sh
```

При выполнении скрипта команды отображаются вместе с результатами. Если одна из команд завершается ошибкой, выполнение продолжается со следующей строки. Команда `exit` завершает выполнение скрипта.

## Обработка ошибок

Эмулятор обрабатывает некорректные команды и аргументы, отсутствующие файлы и каталоги, ошибки навигации, некорректные параметры команд и ошибки загрузки виртуальной файловой системы.

Ошибки выводятся в терминал и не приводят к аварийному завершению программы.
